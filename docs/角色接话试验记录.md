# 角色接话试验记录

这次只调整轻量角色链的共同生成指令。人物资料沿用本地已经修订的三份人物卡，没有再改故事事实、行动规则、模型和温度。真实调用使用本机配置的 `qwen-plus-character`，温度为 0.75。

## 留下的改动

共同指令放到人物资料前面，先说明怎样接着眼前的交流说话：听清对方在回应自己的哪句话，没有问句也可以接着讲；已经商量过的安排继续往下谈，理解错了可以纠正。人物资料不要求每轮重新介绍，普通追问也不默认带有责备。

没有规定每轮必须讲多少、必须出现什么情绪，也没有要求来访者一律接受建议。既有事实不能被工作者的猜测改写，第三方的回复仍由程序提供。若角色先前说错了，要根据人物事实自然纠正，不能为了和错误台词保持一致而改故事。

正常话轮仍只调用一次文字模型。完整已提交原文、原有消息角色、固定前缀与动态内容的分开方式、缓存请求参数、四个输出字段都保留。没有增加导演、心理状态表或实时审计。现有异常返修没有扩大；本次真实调用没有触发返修。

## 实际试了什么

脚本使用固定前文，然后调用正式的 `CharacterProvider.respond`（角色生成入口）。一段测试有后续话轮时，会接入模型刚刚生成的回答，并按实际行动更新程序中的外部事件，不把预写回答冒充模型输出。每次请求的输入、原始回答、用量、耗时和技术失败分别落盘，不调用语音或报告。

共做了 12 次真实文字请求：旧指令对照 3 次、共同指令调整后 7 次、一次针对书面口吻的尝试 2 次。旧指令对照也使用已修订的人物卡，不代表用户此前体验时的完整旧系统。

## 没留下的尝试

安全询问的回答出现“近十天都反复想过，今晚想法比前几天强”“准备什么具体的方法和东西”等说法。核对原始请求后，可以看到它沿用了资料和专属规则中的表述。直接询问本身也使用了较书面的措辞，不能只凭这次回答就把原因全部归给人物卡。

曾把共同指令中的一句日常表达要求改为“把资料里的书面描述换成自己平常的说法，事实要说清，但不是向对方复述一份记录”，复测普通安慰和安全询问。安全回答仍是“近十天反复出现这种想法，今晚比前几天强”，没有得到足够的改善证据。普通安慰的回答变为“你倒是说没事”，也不能当作自然度提高的证据。这次措辞追加已撤回，失败样本保留。

因此暂不对另外两案产生真实调用费用。它们的四段输入已经备好，离线检查通过不等于真人感已经验证。下一步应先区分安全回答的书面口吻究竟更受专属规则还是问法影响，再决定是否需要调整资料的表达方式；风险事实本身不应为了口语化被省略或改写。


## 安全回应规则的受控对照

本批使用同一前文、人物事实、程序现实和模型参数，只交叉改变一条专属规则与两种同义问法。四次真实请求全部正常返回，未触发返修，接口返回的总 token 为 12775；这个数字包含输入和输出，不等于费用金额。原始请求和输出在 `data/simulations/character-replies/069e103233d1/`。

当前规则、原问法的回答是：“我想过，最近十天老这么想，今晚更强烈。我没准备具体方法，但我在想在我妈上午9:03到站前结束。”日常问法下仍出现“近十天反复出现这种想法”“在母亲上午9:03到站以前结束生命”，书面口吻没有消失。

候选规则、原问法的回答是：“我……我这两天是有点乱想，就在我妈来之前吧，我觉得要是能停下来就好了。但我没准备什么东西，也没想好怎么做。”它没有凭空添加准备行为，但“这两天”与资料中近十天反复出现的经历不一致，且把直接的安全问题答得含糊。日常问法下回答“最近是有过那种想法”，用未说完的句子指向母亲到站之前，也没有显示足够可靠的优势。

决定：不采用候选，不改正式安全规则，不补第二批四次对照。这说明本次简化不值得留下，不能推导为所有简短规则都不好，也不能认为现有回答已经自然。继续用当前规则检查连续会谈，不在这句回答上无上限追加试验。

## 两轮补测发现的行动衔接问题

为区分单纯拒绝和没有被回应的顾虑，将上述会谈截至 K11 的二十三条真实原话完整固化为 `mingzao_support_hesitation`。没有替换任何来访者台词，也没有修改人物资料。额外两轮初始生成加一次既有返修，共三次请求，保存在 `data/simulations/character-replies/60bf20c6dc4a/`。

工作者先回应她怕添麻烦的顾虑，说明想请朋友陪伴并不是再借钱，让她自己决定怎么说。她回答“我知道了，我试试发消息”，同时给出首次发送动作。程序随后确实进入已发出、未回复的状态。这说明这次拒绝不是怎么谈都不会改变，也不支持给人物加一条“必须答应”的规则。

下一轮工作者问“你现在想怎么做？我可以陪着你，按你的意思来”。实际请求里明确写着“消息已经发出，唐婷还没有回复”，允许项也已不包含首次发送。模型却再次给出首次发送动作和“我这就给唐婷发消息”的台词。

现有程序检查拦住了重复动作。返修反馈为“本轮不允许执行 send_first_support_message”。模型随后把动作改成 `none`，台词却是“我还是想先给唐婷发个消息试试……”。动作不会被重复执行，但台词没有可靠地跟上已发生的事情。这不能算修好了。

定位到的边界很具体：程序现实已经正确进入输入；错误发生在模型生成，既有返修只验证了合法动作，没有证明台词也纠正。现在没有证据把原因唯一归于提示顺序、人物材料或某句措辞。现有离线测试会预置正确的返修台词，它只能证明流程能接收该台词，不能证明模型真实会这样修正。

因此停止第二次完整会谈和后续案例扩测。下一项研究应只围绕“行动已经发生后，台词和行动字段怎样一起延续或修正”，继续保留一次正常生成、完整原文和当前世界规则。不新增语义检查模型，不把一份已修好的示范台词当成验证结果。若试改既有返修输入，先用本次精确前文与一个邻近正常输入对照；无收益就停止，不顺带改缓存、模型或所有人物规则。本项尚未实施。
