# 角色接话改进安排

## 本轮范围

让人物接着已经发生的事说话，让页面准确说明什么时候收音。保留正常话轮一次文字生成、完整逐字稿、现有缓存与一次返修。原有未提交修改留在当前开发目录，不切分支、不提交、不推送，不改报告侧。

自动补话、打断、依据声音推断情绪、字幕呈现取舍、改变第三方联系结果，均不在本轮加入。

## 任务与顺序

### 一、复核已有会谈

读取两份已保存的连续会谈，按原有五个观察维度逐轮判断，另存审阅稿，不覆盖原始产物。区分人物问题、测试工作者问题、尚无证据；不能把十六轮用尽当成不会自然结束。冻结“拟消息”“已经发送”“收到回复但还没告诉工作者”等片段，供后续有限调用对照。

### 二、接话与现实输入

现有负责模块为 `character_world.py`、`character_kernel.py`、`character_provider.py`。模型仍输出原有四字段，`action_request` 是本轮执行指令；讨论、拟消息、答应但未行动为 `none`。把这项区别写进实际发送给供应商的简短输出约定，不增加关键词判断或语义审核。

现实状态仍由原有世界对象维护。生成输入区分持续状态和本轮第一次遇到的变化：从最近已提交的来访者话轮取得上一轮生成实际看见的世界阶段，与本轮阶段比较。只有收到回复、到门口、进屋等新变化需要提示人物让对方知道，再接着谈；未变化不反复宣布。这个比较不代表受测者已经听到、也不用于评分。

`SupportWorldView` 增加内部阶段值，供会话核心使用；不增加模型输出字段。已存在的 `world_stage_before` 明确记录生成时实际看到的阶段，`world_stage_after` 记录提交后的现实。完整历史、终止、重放接口不变。语音失败重试复用输出时，同时复用当时的现实视图，不能把生成之后才发生的事记成已经给过模型。

连续与恢复验收：首次发送后不再允许首次动作；新回复提示一次；下一轮不重复；重新创建会话核心后能从数据库恢复；生成或语音期间跨越到达时刻，下一轮仍能获知敲门；失败重试不重复执行动作、不消耗未提交变化。原有字段缺省的旧话轮按无已知观察阶段处理，不能编造人物已经传达结果。

测试先行：在现有 kernel、world、message-shape 测试中增加失败用例，再修改负责模块。模型替身只用于断开收费接口，不用它证明模型会自然表达。输出约定与完整原文检查以真正组装的请求为准。

### 三、收音提示（可并行）

仅改 `SessionPage.tsx` 及其测试。根据现有连接、话轮阶段、提交和重说状态显示“本轮已提交，等待回应”“请暂候”“轮到你说话”。不把设备或连接存在说成正在接收输入。现有页面接口不能确认麦克风权限与设备就绪，因此这轮只说明发言时段及通话连接，不宣称设备正在采集。保留现有提交与收音协议，不改实时原文的显示方式。先写等待状态误提示的失败测试，再修改并回归。

### 四、人物材料（可并行）

在三张 `character.json` 的既有段落补齐普通追问需要的事实：沈雯既定的饮酒用药和既往意图说明；苏静知道的同事姓名；周晴非热线场域中少量明确的既往共同经历。旧资料有来源的沿用，新增虚构内容单独说明。地址边界未定，不在这轮补完整门牌。

精确底牌保留；日常叙述可使用自然时间粒度，需要核对时准确说明，风险时间不能改变。避免再堆“自然一点”的重复指令。不更改世界事件结果、披露方式、风险等级与量规。测试先确认材料和场域隔离，再同步人物稿。

## 验证与停止条件

各任务红绿测试通过后，先独立核对是否符合范围，再审代码质量；所有代理停止编辑后跑主链、案例、模拟相关离线回归及前端测试、类型和静态检查。失败先定位，不靠放松断言过关。

离线通过后，优先用冻结片段进行少量真实文字调用，逐项记录初稿、返修、台词与动作，不运行模型档位对比。预算先控制在八次请求内，出现重复同型失败即停下来分析，不用整场重跑代替定位。若片段已有明确改善，再决定完整会谈范围；未实际覆盖的语音和结束结果不写成已验收。

本轮不增加实时模型和新架构；不以关键词强制同意、拒绝、结束或披露。真实调用不可用时保留离线证据，明确未验证内容效果。

## 周晴热线接话落实

用户已认可丰富人物背景，并要求落实不同问法下的接话。继续在当前开发目录修改，保留所有未提交工作，不切换分支、不提交或推送。正常一轮仍一次文字生成，原有一次返修、完整原文、缓存、语音和报告接口均不变。

1. **人物材料。** 在 `boundary_referral_short/character.json` 的热线段落补入已讨论的工作日常、姐姐关系、此前来电中漏讲生活影响及上次说完整的经历；不把这段热线经历投入机构和文字场域。用已有资料核对常见重要追问，资料确实缺失时作少量明确标注的虚构补写，不随机编新诊断、创伤、风险或第三方结果。不再规定开场先说哪句、再问固定坐席。`test_repeat_caller_portrait.py` 先验证缺口，再验证实际人物输入和场域隔离；同步 `docs/案例人物稿.md`，记录补写来源。
2. **共同接话。** 唯一负责处仍为 `CharacterProvider._stable_prompt`。在现有连续交流段落内合并规则：一次多问可以分开接，听不清指代可以澄清；不沿对方错误前提编经历；已试办法说明实际结果；日常细节少量发挥，重要背景不临时编，人物确实不知道才说不知道。不增加分类器、输出字段、工具或模型。先以真实 `_messages` 编译结果验证规则、完整原文和当前话语进入输入，再修改指令。
3. **对照问法。** 复用 `character_conversation_probes.json` 和 `probe-character-responses.py`，增加少量周晴固定前文样本：同义问法、错误前提与修正、已试建议、一次多问、重要背景追问、冒犯后道歉。样本记录预期边界，不规定逐字答案，不把关键词命中当作质量通过。先离线检查样本与真实请求构建，再按明确指定的样本少量调用现有配置的角色模型；不调用语音或报告，不更换模型或温度。首批最多八次文字请求，遇到同型严重错误先停下分析。

输入流保持为人物资料与当前场域 → `CharacterProvider._messages` → 完整已提交原文、最新现实、本轮工作者话语 → 既有四字段输出 → 原有会话提交与呈现。持久化和报告材料不变；人物卡只帮助扮演，不能作为实际受测者行为证据。

验证顺序：原有待实现人物测试的红灯 → 各负责文件定向红绿测试 → 所有代理停止编辑后的运行时、案例、模拟回归与静态检查 → 独立复核 → 有限真实文字试演。既有无关失败单列，不修改报告侧来凑通过。样本生成结果、原始返回、失败和调用次数由原有脚本保留；试验记录写明验证到哪一步，不能用离线全绿声称完整热线已自然可用。
